feature: with `croft hook install` in place, an agent's Edit, Write or MultiEdit now waits on croft. A popup shows the proposed change as a diff against the file on disk. Enter approves, Esc denies, and r denies with a reason the agent reads. Several proposals queue in arrival order.
feature: Go debugging, through delve. F5 on a `.go` file debugs its package, and on a `_test.go` file runs the package's tests under the debugger. A `launch.json` configuration with `"type": "go"` launches or attaches, honouring delve's `mode` (`debug`, `test`, `exec`, or `local` to attach to a `processId`). Breakpoints, conditions, logpoints, stepping, the call stack, variables and watches work as they do for the other languages. croft finds `dlv` on your PATH, in `$GOBIN` or in `$GOPATH/bin`. Without it, croft tells you the `go install` command to run.
feature: config sync to a remote can be switched off per host with `config_sync_excluded_hosts`, or per file with `config_sync_excluded_files` (for example, to keep `keybindings.json` home). Both are user settings that a workspace cannot change. The connect output says what was skipped and why. docs/SETTINGS.md now documents what syncs.
feature: the Explorer has an AGENT LANE section. It lists each coding agent that changed files and, under it, those files, with unreviewed ones first and marked. Clicking a file opens its diff against the version you last reviewed. "Agents: Open Agent Lane" in the palette opens the section, which can also be shown or hidden from the EXPLORER ⋯ menu. It takes no room until an agent has changed something.
feature: `croft record` writes a running `croft attach` session to an asciicast file that `asciinema play` and the agg GIF converter read. It captures the full-colour stream every participant sees, including window resizes. The recorder only watches: it never resizes the session, never types into it, and never takes control from the person who attaches next. Stop it with Ctrl-C or `croft record --stop`. `--out` chooses the file; the default is `croft-session-<time>.cast` in the workspace.
feature: Accepting the "Open workspace here?" offer on an ssh pane opens the remote workspace in the directory the remote shell is in, when that shell reports it (OSC 7), instead of the login directory. A report left over from an earlier session on another host is never used.
feature: Remote provisioning is logged in OUTPUT > Remote: when croft prepares a host, when it installs, and why an install failed.
feature: The history scrubber now shows the file at each commit it steps to, read-only, with the git gutter marking what that commit changed. Your live buffer and its unsaved edits are untouched and come back with Esc; typing while a commit is on screen is refused rather than going into the hidden buffer.
feature: Fleet runs can target `localhost` and running Docker containers (`docker:<name>`) alongside ssh hosts, record how long each host took, and mark which lines of each output differ from the reference output. `*` still means every ssh host only.
feature: Jupyter notebooks run. Click a code cell's ▷ to run it in the notebook's kernel, started from the project's .venv (or any Python with ipykernel). Text, errors and images stream into the cell, and saving writes them to the .ipynb the way Jupyter does. The palette adds Run All Cells, Interrupt Kernel and Restart Kernel.
feature: `croft pr <number>` and **Source Control: Review Pull Request** open a pull request in its own tab: every changed file with its `+n −m` and a viewed checkbox that persists, the checks with their state, and a summary line. Enter shows a file's diff side by side, and on a failing check puts its log in OUTPUT > PR Checks.
feature: `croft demo`, and a **Take the Tour** button on the welcome screen, walk through croft in a throwaway sample project: opening files, Cmd+P, splitting the editor, the terminal, jumping to an error, the command palette and themes. Enter moves on, Esc leaves at any step, and the sample project is deleted either way. The button goes away once the tour has been taken or skipped.
feature: Test coverage. "Testing: Run All Tests with Coverage" marks each line of a covered file in the editor gutter (ran, never ran, or a branch missed) and shows the file's percentage in the status bar. It works with pytest, vitest, jest and Rust (cargo-llvm-cov). Marks dim once you edit the file. A missing coverage tool is offered for install, and "Coverage: Clear" hides the marks.
feature: Test watch mode. Click the eye on a test or suite in the Testing view (or `w` for everything) and croft reruns it whenever you save a file in the project. When a watched run turns red, the badge and status line say which test failed, and "Testing: Go to First Failure" jumps to it. Green runs stay quiet.
feature: when croft was installed from crates.io, `croft remote` installs the matching release binary on the remote instead of compiling one. It is downloaded on your machine, checked against the release's SHA256SUMS, and shipped over SSH, so the remote needs no internet access and the first connect is seconds rather than minutes. A source checkout still builds from its own source. `croft remote --build` forces a build, and a version with no published release binaries falls back to building automatically.
