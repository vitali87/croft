fix: Stage Hunk and Revert Hunk apply at the hunk's own lines. When an earlier change shifted the file and the same context appeared nearby, git could apply the patch in the wrong place, staging a line at the wrong spot or deleting the wrong lines from your file.
fix: Discard on a Changes row restores the file from the index, as VS Code does, so the staged part of a partly staged file is kept. Before, it went back to HEAD and threw the staged work away too.
fix: hunk and line actions (stage, unstage, revert) work when the workspace is a subfolder of the repository. They used to send a path relative to the workspace, and git refused it or changed a same-named file at the repository root.
fix: saving a file that had bytes invalid in its encoding (shown as �) now asks first. Before, it silently replaced the original bytes. Reopen with Encoding keeps them.
fix: in the merge editor, typing on the line just after a conflict no longer marks that conflict resolved and drops both sides. Auto save also skips a merge that still has open conflicts.
fix: staging or unstaging a path with glob characters, such as Next.js's `pages/[id].tsx`, touches only that file. It used to stage matching files too, untracked ones included.
fix: discarding an untracked folder keeps the ignored files inside it, like `.env` or `node_modules/`.
