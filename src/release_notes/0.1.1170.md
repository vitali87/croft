fix: A remote launched from a croft release binary (a release tarball or cargo binstall) now updates when the local croft does. Before, its install was stamped with a hash of a source folder that was not there, the same value for every version, so after the first install the remote never updated and F9 never offered the relaunch. Such a croft now also installs the remote from the prebuilt release binary (part of #261).
