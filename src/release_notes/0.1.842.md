fix: a runnable block's captured output is now tied to its command by a stable id rather than by position in the pane's command list, so a long-running block whose own output scrolls older marks away no longer shows, or writes, a different command's output. A command that finishes in the instant between confirming a block and its keystrokes reaching the shell can still be captured instead; that window is unchanged and self-corrects on the next run.
