feature: A QL icon in the activity bar opens the CodeQL side bar, laid out like VS Code's CodeQL extension: Language, Databases, Queries, Variant Analysis Repositories, Query History, AST Viewer and Method Modeling, each with its getting-started actions. CodeQL is a built-in row in the Extensions view; disabling it removes the icon and the side bar.
feature: `.sarif` files open in a results viewer. Results are grouped by file, rule or log, with level, baseline and suppression filters and a search box (`rule:`, `file:`, `level:`, `tag:`, `-term`, `a|b`). Enter opens a result at its line and column and keeps the viewer tab open. A log that is not SARIF 2.1.0, or not valid JSON, opens as text with the reason.
feature: debug configurations honour `postDebugTask`. The named task from tasks.json runs once when the debug run ends, whether you stop it or the program finishes, and not when a new launch replaces the old one. In a compound, each member's task runs once, in launch order. A task name that tasks.json does not declare is reported in the status line.
feature: an lldb attach configuration can say `"processId": "${command:pickProcess}"`, as in VS Code. Starting it opens a list of your processes to choose from, instead of failing on an unknown variable. croft does not list itself. On python and node configurations, which attach by other means, the placeholder is refused with a message.
feature: the Run and Debug panel lists every breakpoint under BREAKPOINTS, as VS Code does, by file and line, with a conditional breakpoint's condition or a logpoint's message beside it. The list shows at rest as well as while debugging. Clicking an entry opens the file at that line. Its ✕ removes the breakpoint, including from a session that is running.
feature: The CodeQL side bar's Databases section works: add a database from a folder, an archive, a URL or a GitHub repository (via `gh`), see the added ones listed with their language, and pick the one queries will run against. The list is remembered between sessions.
feature: "CodeQL: Run Query on Selected Database" runs the open `.ql` file against the selected database. An alert query (`@kind problem` or `path-problem`) opens its results in the SARIF viewer; any other query opens a CSV table. Each run is kept in the Query History section, and clicking an entry reopens its results.
