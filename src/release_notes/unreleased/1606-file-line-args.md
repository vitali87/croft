fix: `croft big.txt:150`, `croft --open-file big.txt:150:3`, and `croft edit` or `croft view` with a `file:line[:col]` argument now open the file with the caret on that line and column, as compilers, `grep -n` and stack traces print locations. Before, the launch failed with "resolving workspace path", and `croft edit` created an empty file named `big.txt:150`. A file whose own name ends in `:N` still opens as itself.
