fix: settings now load from the active profile, where croft saves every change. Before this, a profile's settings were saved but ignored at the next launch.
fix: inline suggestions ask once per caret position. An empty answer, an error or a dismissed suggestion no longer re-sends the request on every tick, which could make hundreds of paid calls a second.
fix: Markdown lint no longer treats a line starting with inline code (```` ```ls``` ````) as a code fence, which skipped every check for the rest of the document. A ```` ```js ```` line inside a code block no longer ends the block.
fix: the screen reader command reads a file name starting with `-` as text, not as one of its own options.
fix: PR review comments on files whose path has a space or non-ASCII characters now post inline instead of being listed in the review summary. The same goes for comments below an added line that starts with `++`.
fix: bookmarks follow their line through Move Line Up/Down and its undo.
fix: an edit mirrored from another tab of the same file moves that tab's extra carets along with the main caret.
fix: in a symbol tab, Enter at the end of the symbol's last line grows the symbol even after another tab typed on that line.
fix: the Markdown preview of a very long document scrolls to the right place when jumping from the source.
fix: `git rebase -i` in a pane opens its plan in croft again after croft was updated while running. Before this, the pane pointed git at the replaced binary's `(deleted)` path, and the rebase aborted.
fix: with a profile active, disabling an extension and granting or revoking an MCP consent are saved to the profile, which is what croft reads at start. Before this, a disable was undone on restart, and a revoked consent could come back.
fix: settings are saved by writing aside and renaming, so the MCP tool check never reads a half-written config and refuses an unchanged tool.
